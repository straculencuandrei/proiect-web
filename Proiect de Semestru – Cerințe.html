Proiect de Semestru: Portofoliu Web Dinamic (GitHub API Integration)

Obiectivul Proiectului

Dezvoltarea unei pagini web personale (CV / Portofoliu) care se integrează dinamic cu API-ul oficial GitHub pentru a prelua și afișa proiectele personale ale studentului într-un mod atractiv și organizat.

Cerințe Obligatorii (nota 5 - 7)

  1. Arhitectură și Conținutul Paginii
    • Secțiune Profil: Pagina trebuie să conțină o secțiune de introducere (Nume, Rol/Tehnologii preferate, o scurtă descriere și o poză de profil).
    • Secțiune Portofoliu: O zonă dedicată unde vor fi încărcate dinamic repository-urile de pe GitHub.
    • Experiență de muncă (dacă există): Include experiență relevantă în domeniul IT sau alte joburi, cu rol, companie și perioadă (ex: "Front-end Developer — Compania X — 2022‑2023").
    • Educație: Include nivelul de educație, instituția și perioada (ex: "Facultatea de Informatică, Universitatea Y — 2020‑2024").
    • Personalizare: Pagina/paginile trebuie sa aibă un design unic și personalizat - care să reflecte ceva specific studentului.
  2. Integrarea cu GitHub API (Frontend/Fetch)
    • Efectuarea unui request asincron (folosind fetch sau axios în JavaScript) către endpoint-ul public: https://api.github.com/users/USERNAME/repos.
    • Afișarea a cel puțin 5 proiecte sub formă de carduri (cards).
  3. Informații minime per Card de Proiect
    • Numele repository-ului (name).
    • Descrierea proiectului (description) – Dacă descrierea lipsește pe GitHub, se va afișa un text default (ex: "Fără descriere disponibilă").
    • Limbajul principal de programare (language).
    • Numărul de stele (stargazers_count) și numărul de fork-uri (forks_count).
    • Un buton/link funcțional către codul sursă de pe GitHub (html_url).
  4. Design și Responsivitate

    Interfața trebuie să fie complet responsivă (telefon, tabletă, desktop). Se pot folosi CSS Grid/Flexbox sau framework-uri precum Tailwind CSS / Bootstrap.

Notă: Pentru cazul in care sunt putine proiecte, se va afișa un mesaj corespunzător si mai apoi se vor afișa o lista hardcodata de proiecte citite dintr-un json sau o listă de proiecte incarcate pe un database hostat local(MySQL ...).

Cerințe Medii (nota 8 - 9)

  1. Filtrare și Sortare (Client-side)
    • Excluderea Fork-urilor: Proiectele afișate trebuie să fie doar cele create de student (fork === false).
    • Ordonare: Proiectele trebuie sortate automat după data ultimei actualizări (updated_at) sau după numărul de stele.
    • Sistem de filtrare în pagină: Implementarea unei bare de căutare (Search Input) sau a unor butoane de filtrare după limbajul de programare, care să filtreze cardurile în timp real, fără a reîncărca pagina.
  2. Experiența Utilizatorului (UX/UI)
    • Stare de Loading: Afișarea unui spinner sau a unui schelet de animație în timp ce se așteaptă răspunsul de la API.
    • Tratarea Erorilor (Error Handling): Dacă API-ul dă eroare (ex: limită de request-uri atinsă, utilizator inexistent, lipsă internet), aplicația nu trebuie să crape. Se va afișa un mesaj prietenos în UI (ex: "Ups! Nu am putut încărca proiectele momentan.").

Cerințe Avansate / Bonus (măcar 1 subpunct pentru nota 10)

  1. Securitate și Backend (Serverless / Proxy)
    • Pentru a evita limita de request-uri (Rate Limiting) de 60/oră a GitHub, studenții trebuie să genereze un Personal Access Token (PAT).
    • Cerință strictă: Token-ul NU are voie să apară în codul din browser (Frontend).
    • Studentul trebuie să creeze un mini-server proxy (Node.js/Express, funcții Serverless în Vercel/Netlify sau PHP) care să facă cererea securizată către GitHub (folosind variabile de mediu .env) și să servească datele către frontend.
  2. Paginare sau "Load More"

    Dacă utilizatorul are mai mult de 6 proiecte, se va implementa un sistem de paginare sau un buton de "Load More" pentru a nu aglomera pagina la încărcare.

  3. Detalii suplimentare (ReadMe / Deploy)
    • Deploy: Proiectul trebuie să fie live (funcțional) pe o platformă gratuită (GitHub Pages, Vercel, Netlify).
    • README profesional: Proiectul în sine trebuie să aibă un fișier README.md pe GitHub bine structurat, cu instrucțiuni de instalare locală și tehnologiile folosite.

Notă: Pentru a obține o notă precum cele menționate în paragrafele de mai sus, trebuie să aveți idee despre ce se cere, cum ați (sau mai bine "ați") implementat cerințele și pe alocuri să faceți modificări la cod.
